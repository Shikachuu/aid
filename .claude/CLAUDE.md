# `aid` project instructions

`aid` is a single-binary documentation tool that generates static documentation sites from markdown, HTML, OpenAPI, and Protobuf sources. See @docs/PRODUCT_OVERVIEW.md and @docs/RESEARCH_stack.md for the full overview and stack rationale.

## Stack

| Area | Choice |
| --- | --- |
| Runtime | Bun canary `1.4.4-canary.20261103.1` (mise `http:bun` pin), the first build with `bun lint` |
| Language | TypeScript, strict mode, ESM only |
| Lint and format | `bun lint` and `bun fmt`, configured in the generated `bunfig.toml` and `.prettierrc.json` |
| Styling | Tailwind 4 |
| JSX runtime | custom (`@aid/jsx`, mapped in `tsconfig.json`) |

## Scripts

| Command | Purpose |
| --- | --- |
| `bun run check` | Local merge gate: tests, typecheck, lint, every `--check`, `deps:binaries --offline`, and `docs:lint` |
| `bun run build` | Run `scripts/compile.ts`: emit the schema, bundle the browser runtime, and cross-compile the release binaries |
| `bun run emit-schema` | Emit `schemas/aid.schema.json` from Zod |
| `bun run typecheck` | `tsc --noEmit` |
| `bun run lint` | `bun lint` over the code, then `aid lint --filter css` over every CSS file |
| `bun run fmt` | `bun fmt` over the code, JSON, and CSS |
| `bun run gen-bunfig` | Generate `bunfig.toml` and `.prettierrc.json` from the bundled defaults plus the repo extras (`--check` fails on drift) |
| `bun run gen-css-data` | Generate `src/lint/css-data.json` from the webref packages (`--check` fails on drift) |
| `bun test` | Bun test runner |
| `bun run gen-docs` | Generate `site/docs/reference/**` from the Zod schemas, CLI definitions, and lint tables (`--check` fails on drift) |
| `bun run docs:dev` | Serve the docs site at `http://localhost:3000/aid/` with live reload |
| `bun run docs:build` | Build the docs site into `site/dist` |
| `bun run docs:lint` | Run `aid lint --filter md` over `site/` |
| `bun run docs:affected` | List docs pages mapped to the files changed since `origin/main` |
| `bun run deps:binaries` | Check platform packages, staged natives, and the Bun pin for drift, and list upstream updates (`--offline` skips the lookup) |

Run the CLI from source with `bun src/cli/index.ts <command>`, for example `bun src/cli/index.ts dev`.

## Documentation

`site/` is aid's documentation site, built by aid. Behavior changes ship their docs in the same change: run the `docs-sync` skill (`.claude/skills/docs-sync`) after changing anything users or contributors see. `site/docs/reference/**` is generated by `bun run gen-docs`.

## Where the rules live

Style and convention rules are split across `.claude/rules/`. Files without `paths:` frontmatter load every session. Path-scoped files load when Claude touches a matching file.

## Hooks

A PostToolUse hook formats each edited code, JSON, CSS, and markdown file (`.claude/hooks/format-on-edit.sh`): `bun fmt` plus `bun lint --fix` for code, aid's own markdown formatter for `.md`. It skips generated files and gitignored paths, and reports a formatter failure back to Claude. Do not format files you edited with Edit or Write yourself. Files changed through Bash are not hooked: run `bun fmt --no-script <files>` on them.
