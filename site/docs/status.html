Status

aid has no published release. This page lists the features that exist in the code but do not work yet, and the ones that work with known gaps.

Not implemented

FeatureCurrent behavior
aid init Prints aid init <dir>: not implemented and exits 1. Create the project files by hand as getting started shows.
ai_targets config key aid validates the value against chatgpt, claude and gemini, then never reads it.
"Open in AI" button Markdown, HTML, OpenAPI and Protobuf pages render the button. Its click handler in src/web/ai-button.ts is empty, so a click does nothing.
Dark-mode toggle button The header renders the button. Its click handler in src/web/dark-mode.ts is empty. The theme.dark_mode key still controls the dark palette; see dark mode.
Template and partial overrides The page layout is built into aid and cannot be replaced. dir.templates supplies only the llms.txt template, and Tailwind scans that folder for class names.
HTML body fragments An .html page must be a full document with <html> and <body>. A fragment fails the build.
Mobile sidebar layout The page is a fixed two-column grid with a 16rem sidebar at every screen width. There is no collapsed menu for narrow screens.
sitemap.xml, robots.txt, 404 page, canonical tags aid generates none of them. A robots.txt or 404.html placed in the static folder is copied to the output root as-is.
Versioned docs A build produces one version of the site. There is no version switcher.
Windows binaries scripts/compile.ts builds only darwin-arm64, darwin-x64, linux-arm64 and linux-x64.

Partly working

FeatureWhat worksKnown gaps
Compiled binaries bun run build writes four binaries to dist/bin/, and they build sites when run inside a checkout of the aid repository. A darwin-x64 binary cross-compiled on Apple silicon carries an invalid ad-hoc signature, and macOS kills it on start until you re-sign it. Outside the aid repository the darwin-arm64 binary fails on start with Cannot find module '@bufbuild/buf-darwin-x64/bin/buf'. Every binary also reads Biome's biome_wasm_bg.wasm from the build machine's node_modules path, so aid lint fails with ENOENT elsewhere. See installation.
Rebuilds aid build and aid dev build the whole site. There is no incremental rebuild. Every aid build and every dev-server rebuild renders every page again.
OpenAPI detection in aid lint and aid fmt The build detects OpenAPI files by content: a top-level openapi: or swagger: key. aid lint and aid fmt find OpenAPI files by name only: openapi.*, *.openapi.*, and files under an openapi/ folder. A spec named api.yaml builds as an OpenAPI page but is not linted or formatted. See linting.
